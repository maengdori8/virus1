| 항목 | 내용 |

| 장르 | 턴제 생존 + 자원관리 + RPG 전투 |

### 세계관 / 왜 한의사인가

인트로 텍스트(`StoryUI.pages`)에 그대로 들어 있다. 발표자가 스토리를 못 짚으면 이걸 읽으면 된다.

> 한약이 맛있어서 한의사가 됐다 → 스스로를 실험 대상으로 삼아 평생 약을 삼켰다 → 바이러스가 퍼져 도시가 무너졌다 → 사람들은 정신을 잃었는데 **나만 의식이 남았다** → 평생 삼킨 약들이 무슨 짓을 한 모양이다 → 의식이 남아 있는 동안 내 방식대로 치료제를 만든다.

이 설정이 **게임 시스템 두 개를 그대로 정당화한다.**
- **의식 게이지**: 주인공만 의식이 남았지만 그것도 매일 흐려진다. 그래서 시간 압박이 서사와 붙는다.
- **오행(五行) 전투**: 한의사니까 서양식 스탯이 아니라 목·화·토·금·수 상성으로 싸운다.

> **질문 대비**: "왜 오행이에요?" → "주인공이 한의사라서요. 속성 상성을 굳이 판타지 원소로 안 쓰고 한의학 오행으로 갈아끼운 겁니다. 상극 관계(목극토·토극수·수극화·화극금·금극목)를 그대로 코드에 넣었습니다."

## 2. 하루 루프 — 게임이 어떻게 굴러가는가

이게 발표의 뼈대다. 이것만 정확히 설명해도 절반은 끝난다.

```
[낮] Ingame 씬 (벙커)
  ├─ 물자 소비 (dailyCost)  → 물자 모자라면 모자란 만큼 체력이 깎인다
  ├─ 체력 자연회복 (dailyHeal) → 단, 의식이 혼미하면 회복 없음
  ├─ 의식 감소 (dailyDrift) → 임계치 이하면 추가 체력 손실
  ├─ 게임오버 / 클리어 판정
  │
  ├─ [연구] Research 씬 → 샘플 소모 → 전투 → 이기면 백신 진행도 +
  └─ [탐사] Adventure_Enter 씬 → 지역 선택 → Adventure 씬

[밤] Adventure 씬 (바깥)
  ├─ 스태미나 = 그 지역의 한도로 세팅 (지역마다 다름)
  ├─ 랜덤 이벤트 → 선택지 (각각 스태미나 소모) → 보상/패널티
  ├─ 전투 이벤트면 → 전투 (여기선 스태미나가 실제로 닳는다)
  ├─ 더 들어가기 → 깊이 +1, 샘플 추가 획득, 대신 스태미나 대량 소모
  ├─ 휴식 → 시간 턴 1 소모하고 스태미나 회복
  └─ 복귀 → 시간 턴 1 소모 → 낮으로

[시간] 시간 턴이 0이 되면 → 하루 종료 → 남은 날짜 -1, 누적 일수 +1
```

**중요한 설계 포인트 3개** (질문 오면 이걸로 답한다)

1. **시간은 "행동"으로만 흐른다.** 실시간이 아니라 복귀·휴식 같은 행동이 시간 턴을 깎는다. 그래서 플레이어가 "오늘 뭘 할지"를 온전히 통제한다.
2. **밤에 얻고 낮에 잃는다.** 밤은 이득(샘플·아이템), 낮은 비용(물자·체력·의식). 그래서 "한 번 더 나갈까, 그만할까"가 매 턴 선택이 된다.
3. **스태미나는 하루 자원이 아니라 밤 자원이다.** 탐사 시작 시 그 지역 한도로 리셋된다. 지역마다 한도가 달라서 지역 선택 자체가 전략이 된다.

## 4. 아키텍처 — "왜 이렇게 짰냐"에 대한 답

이 3개가 이 프로젝트에서 **제일 자신 있게 말할 수 있는 설계 결정**이다.

### 4-1. 모든 상태를 `GameState` 하나에 모았다 (ScriptableObject)

```csharp
public class GameState : ScriptableObject {
    public int currentDay;              // 누적 일수 (= 랭킹 점수)
    public TimeData time;               // 남은 날 / 하루 턴 / 하루 최대 턴
    public HpData hp;                   // 현재 / 최대 / 일일 회복
    public StaminaData stamina;         // 현재 / 최대
    public SupplyData supply;           // 보유 / 일일 소비
    public int[] sampleInventory;       // 바다 / 산 / 도시
    public PlayerBattleData battle;     // 공격 / 방어 / 오행 속성
    public int vaccineProgress;         // 0~100 (100이면 클리어)
    public int reasearchCleared;        // 깬 연구 단계 수
    public int consciousness;           // 0~100
    public List<ItemSO> itemInventory;  // 보유 아이템
}
```

**왜 SO인가?** 씬이 5개인데 씬을 넘나들어도 상태가 유지돼야 한다. 보통 `DontDestroyOnLoad` 싱글턴을 쓰는데, 그러면
- 어느 씬에서 시작해도 그 오브젝트가 있어야 해서 테스트가 불편하고
- 인스펙터에서 값을 볼 수가 없다.

SO로 빼면 **에셋 파일 하나가 곧 게임 상태**라서, 에디터에서 플레이 중에 값이 실시간으로 보이고 직접 고쳐가며 테스트할 수 있다. 각 매니저는 인스펙터에서 이 에셋 하나만 물면 된다.

> **날카로운 질문 대비**: "SO는 에디터에서 값이 영구 저장되는데요?"
> → "맞습니다. 그래서 `GameInitializer.Init()`이 판 시작마다 전 필드를 초기값으로 덮어씁니다. 에디터에서 값이 남는 건 오히려 디버깅에 유리해서 의도적으로 둔 겁니다. 빌드에서는 애초에 에셋에 안 써집니다."

### 4-2. SO 언로드 버그와 `KeepLoaded()` — 실제로 겪은 문제

```csharp
public void KeepLoaded() {
    hideFlags = HideFlags.DontUnloadUnusedAsset;
}
```

**증상**: 탐사 입구 씬을 거치면 그때까지 모은 샘플이 전부 0이 됐다.

**원인**: Unity는 씬을 넘길 때 **아무도 참조하지 않는 에셋을 메모리에서 내린다.** 탐사 입구 씬은 매니저가 하나도 없어서 `GameState`를 붙들고 있는 오브젝트가 없었다. 그래서 에셋이 통째로 언로드됐다가 **다음 씬에서 파일에서 다시 읽혔고**, 런타임에 쌓아둔 값이 전부 파일에 저장된 초기값으로 되돌아갔다.

**해결**: 판 시작할 때 한 번 `hideFlags`에 "안 쓰여도 내리지 마라" 플래그를 세운다.

> 이건 **발표에서 제일 좋은 소재**다. "Unity 특유의 함정을 직접 만나서 원인을 추적하고 해결했다"는 서사가 그대로 나온다.

### 4-3. 매니저는 하나에 하나씩 (단일 책임)

| 매니저 | 하는 일 | 안 하는 일 |
|--------|---------|------------|
| `GameManager` | 하루 루프, 게임오버/클리어 판정 | 전투도 탐사도 직접 안 함 |
| `TimeManager` | 턴 감소, 날짜 넘김 | 시간이 흐를 때 뭘 할지는 모름 |
| `SupplyManager` | 물자 소비, 부족분 체력 차감 | |
| `StaminaManager` | 스태미나 소모/회복/소진 패널티 | |
| `ConsciousnessManager` | 의식 감소, 혼미 판정 | |
| `RewardManager` | `ActionData` 하나를 GameState에 반영 | |
| `ItemManager` | 아이템 사용 | 전투용 약은 거부 (전투가 처리) |
| `ExplorationManager` | 탐사 진행, 깊이, 이벤트 추첨 | |
| `ResearchManager` | 단계 해금, 샘플 소모, 연전 | |
| `BattleManager` | 전투 턴 전부 | UI를 전혀 모름 |
| `RankManager` | 저장/정렬/불러오기 | |

**핵심**: `BattleManager`는 UI를 모른다. 콜백(`onWin`/`onLose`)만 받는다. 그래서 **똑같은 전투 코드가 연구 전투와 탐사 전투에 그대로 쓰인다.** 연구는 "이기면 다음 적", 탐사는 "이기면 보상 받고 탐사 계속"만 콜백으로 다르게 넘긴다.

`RewardManager`도 같은 얘기다. 이벤트 선택지 보상, 전투 승리 보상, 아이템 사용 효과가 **전부 `ActionData` 하나로 통일**돼 있어서 적용 코드가 한 군데다.

```csharp
public class ActionData {
    public int hpChange, staminaChange, consciousnessChange;
    public int suppliesChange, vaccineChange;
    public int[] sampleChange;      // 바다/산/도시
    public ItemSO[] itemGain;
}
```

> **질문 대비**: "확장성은요?" → "새 이벤트를 추가할 때 코드를 안 건드립니다. `EventSO` 에셋 하나 만들어서 선택지 텍스트와 `ActionData` 수치만 채우면 끝입니다. 실제로 이벤트 21개를 그렇게 만들었습니다."

## 5. 시스템별 상세

### 5-1. 시간 (`TimeManager` / `TimeData`)

```csharp
public void SpendTimeTurn() {
    gameState.time.timeTurn--;
    if (gameState.time.timeTurn <= 0) EndDay();
}
private void EndDay() {
    gameState.time.timeTurn = gameState.time.maxTimeTurn;
    gameState.time.dayTurn--;      // 남은 날 감소
    gameState.currentDay++;        // 누적 일수 증가 (랭킹 점수)
}
```

- **시간 턴을 쓰는 행동**: 탐사 복귀, 탐사 중 휴식. 이 둘뿐이다.
- `dayTurn`이 0이 되면 게임오버("기간 초과").
- `currentDay`는 클리어 시 랭킹 점수로 그대로 쓰인다. **적을수록 좋다.**

**밸런스에서 제일 크게 손본 값이 `maxTimeTurn`이다.** 원래 5였다. 하루에 5번 나갔다 와야 하루가 지난다는 뜻이라, "30일 제한"이 실제로는 150밤이었다. 이걸 **1로 바꿨다.** 1밤 = 1일이 되면서 "30일"이 진짜 30밤이 되고, 휴식이 하루를 통째로 쓰는 진짜 트레이드오프가 됐다.

> **질문 대비**: "왜 30일에서 14일로 줄였어요?" → "`maxTimeTurn`을 1로 바꾸면서 날짜 단위가 완전히 달라졌습니다. 예전엔 30이 실질 150밤이었는데 이젠 30이 그대로 30밤입니다. 목표 플레이 타임을 10~12밤으로 잡아서 14일로 맞췄습니다."

### 5-2. 물자 · 체력 (`SupplyManager` / `HpData`)

```csharp
public void ConsumeDaily() {
    gameState.supply.current -= gameState.supply.dailyCost;
    if (gameState.supply.current < 0) {
        gameState.hp.current += gameState.supply.current;  // 음수를 더함 = 부족분만큼 깎임
        gameState.supply.current = 0;
    }
    gameState.hp.Clamp();
}
```

물자가 모자라면 **부족분이 그대로 체력 피해**가 된다. 굶으면 죽는다는 걸 별도 시스템 없이 뺄셈 한 줄로 표현했다.

체력은 `dailyHeal`만큼 매일 자연회복되는데, **의식이 혼미하면 회복이 통째로 막힌다.**

```csharp
bool dazed = consciousnessManager != null && consciousnessManager.IsLow();
if (!dazed) HealDaily();
```

> **왜 막았나 (중요)**: 원래는 혼미 페널티가 체력 -3인데 자연회복이 +5라서, **혼미에 빠져도 순이득**이었다. 페널티가 페널티가 아니었다. 회복 자체를 막아야 혼미가 진짜로 무서워진다.

### 5-3. 의식 (`ConsciousnessManager`) — 이 게임의 시계

```csharp
public void Tick() {
    gameState.consciousness -= dailyDrift;   // 매일 8씩
    Clamp();
    if (IsLow()) {                           // 30 이하면 혼미
        gameState.hp.current -= lowHpPenalty; // 매일 추가 6
        gameState.hp.Clamp();
    }
}
```

- 100에서 시작해 **매일 8씩 떨어진다.** 임계치 30 이하가 되면 혼미.
- 혼미 상태: **자연회복 차단 + 매일 체력 6 추가 손실.** 이중 페널티다.
- 회복 수단: 연구 단계 클리어 보상, 진정제 아이템.
- 상단 HUD의 **얼굴 그림이 3단계로 바뀐다** (>66 명료 / >33 흐림 / 그 이하 혼미).

계산: 100에서 8씩 → **9밤째에 혼미 진입.** 목표 클리어가 10~12밤이라 "막판에 몸이 무너지기 시작하는데 그 전에 끝내야 한다"는 압박이 딱 걸린다.

> **질문 대비**: "의식은 왜 넣었어요?" → "스토리에서 주인공만 의식이 남아 있다는 설정이 핵심인데, 그게 게임 시스템으로 안 드러나면 텍스트로만 남습니다. 그래서 의식을 매일 깎이는 게이지로 만들고, 얼굴 그림이 흐려지게 해서 플레이어가 자기 상태를 눈으로 보게 했습니다."

### 5-4. 탐사 (`ExplorationManager`)

**지역 선택 → 스태미나 한도 세팅**
```csharp
public void StartExploration(ExplorationSO area) {
    gameState.battle.element = area.element;      // 다녀온 지역 속성 = 내 속성
    gameState.stamina.current = area.staminaLimit;
    staminaManager.ResetPenalty();
}
```

**지역 속성이 내 속성이 된다** — 이게 이 게임의 숨은 전략층이다. 밤에 어디를 다녀왔느냐가 **다음 낮의 연구 전투 상성까지 결정한다.** 코드에 주석으로 "버그 아님"이라고 명시해뒀다.

> **질문 대비**: "속성이 왜 지역 따라 바뀌어요?" → "의도한 겁니다. 밤에 다녀온 지역의 기운이 몸에 남는다는 컨셉이고, 게임적으로는 '보스 상성에 맞는 지역을 골라서 다녀와야 한다'는 층을 하나 더 만듭니다. 밤 선택이 낮 전투에 영향을 주게 묶은 거죠."

**이벤트 추첨 — 같은 게 연달아 안 나오게**
```csharp
int index = Random.Range(0, pool.Length);
if (pool[index] == lastEvent)
    index = (index + Random.Range(1, pool.Length)) % pool.Length;
```
순수 랜덤이면 같은 이벤트가 두 번 연달아 뜨는데, 플레이어 눈에는 그게 **버그로 보인다.** 직전 것이 뽑히면 다른 걸로 밀어낸다. 리롤 반복이 아니라 오프셋 한 번이라 무한루프 위험이 없다.

**깊이 시스템**
```csharp
public bool GoDeeper() {
    if (depth >= maxDepth) return false;
    depth++;
    bool depleted = staminaManager.Spend(deeperStaminaCost * depth);  // 10, 20, 30
    if (depleted) Return();
    return true;
}
private void ApplyDepthBonus(ActionData result) {
    for (int i = 0; i < result.sampleChange.Length && i < 3; i++) {
        if (result.sampleChange[i] <= 0) continue;
        gameState.sampleInventory[i] += depth;   // 곱셈이 아니라 덧셈
    }
}
```
- 깊이당 샘플 **+depth 추가 획득**. 대신 들어가는 값이 점점 비싸진다.
- **왜 곱셈이 아니라 덧셈인가**: 곱하면 원래 획득량이 큰 선택지만 계속 불어나서 "무조건 깊이 들어가고 큰 선택지만 고른다"가 정답이 돼버린다. 덧셈이면 작은 선택지도 같은 이득을 봐서 선택지가 살아남는다.

**휴식**
```csharp
public void Rest() {
    int beforeDay = gameState.time.dayTurn;
    timeManager.SpendTimeTurn();
    staminaManager.Gain(restStaminaGain);
    if (gameState.time.dayTurn < beforeDay) gameManager.StartDay();
}
```
> **여기 버그 하나를 직접 잡았다**: 원래는 휴식으로 날짜가 넘어가도 하루 소비(물자·체력·의식)가 안 치러졌다. 그래서 **밤에 눌러앉아 쉬기만 하면 아무 대가 없이 샘플을 무한정 모을 수 있었다.** 날짜가 넘어갔는지 확인해서 `StartDay()`를 직접 부르게 고쳤다.

### 5-5. 스태미나 (`StaminaManager`) — 소진 패널티

```csharp
public bool Spend(int amount) {
    if (gameState.stamina.current <= 0) return false;   // 이미 0이면 아무것도 못 함
    gameState.stamina.current -= amount;
    if (gameState.stamina.current > 0) return false;
    gameState.stamina.current = 0;                      // 음수 방지 (게이지가 뒤집힘)
    if (penaltyApplied) return false;
    ApplyPenalty();                                      // 보유 아이템 50% 손실
    penaltyApplied = true;
    return true;
}
```

스태미나가 0이 되면 **가진 아이템의 절반을 뒤에서부터 잃는다.** 그리고 탐사가 강제 종료된다.
- 패널티는 **탐사 한 번에 한 번만** 터진다 (`penaltyApplied` 플래그, 탐사 시작 시 리셋).
- 음수 클램프가 있는 이유: 게이지 UI가 `current/max`로 채워지는데 음수가 되면 바가 뒤집혀 보인다.

### 5-6. 샘플 · 연구 (`ResearchManager`)

샘플은 **바다 / 산 / 도시 3종**이고, 연구 단계마다 요구량이 다르다.

```csharp
public void StartStage(int index) {
    if (!IsStageUnlocked(index)) return;              // 이전 단계 클리어 필요
    if (battleManager.InBattle()) return;             // 전투 중 재진입 차단
    if (!CanStartStage(stage)) return;                // 샘플 부족
    for (int i = 0; i < costCount; i++)
        gameState.sampleInventory[i] -= stage.sampleCost[i];
    staminaManager.Spend(enterStaminaCost);           // 입장 시 한 번만
    battleManager.StartBattle(stage.enemies[0], OnStageWin, OnStageLose);
}
```

**방어 코드 3중**: 잘못된 인덱스 / 잠긴 단계 / 전투 중 재진입. 특히 세 번째는 **실제 버그였다.** 전투 중에 카드를 또 누르면 샘플만 한 번 더 깎이고 진행 중이던 전투가 덮어써졌다.

**연전 구조**
```csharp
private void OnStageWin() {
    enemyIndex++;
    if (enemyIndex < stage.enemies.Length) {
        battleManager.StartBattle(stage.enemies[enemyIndex], OnStageWin, OnStageLose, false, true);
        //                                                    스태미나 안 씀 ↑    약효 유지 ↑
        return;
    }
    gameState.vaccineProgress += stage.progressGain;
    gameState.reasearchCleared = stageIndex + 1;
    // 추가 보상: 스태미나 최대치 + / 체력 회복 / 의식 회복
    if (stageIndex == stages.Length - 1) gameState.vaccineProgress = 100;  // 최종보스
}
```
- 3단계는 **변이체 베타 → 숙주 연전**이다. 한 판이 이어지는 거라 **약효(버프)를 그대로 들고 간다.**
- 왜 유지하나: 안 그러면 앞 적한테 약을 쓴 순간 보스 앞에서 맨몸이 되는데, **그걸 알 방법이 화면에 없다.** 플레이어가 알 수 없는 정보로 손해 보게 하면 안 된다.
- **연구 전투는 스태미나를 안 쓴다.** 벙커 안이라 입장 비용만 한 번 낸다. 전투가 길어져도 추가 소모가 없다.

**연구 카드 UI (`ResearchUI`)** — 왜 못 누르는지가 버튼에 그대로 적힌다.

| 상태 | 버튼 문구 |
|------|-----------|
| 이미 깸 | 완료 |
| 이전 단계 미클리어 | 잠김 |
| 샘플 부족 | 샘플 부족 |
| 가능 | 연구시작 |

샘플 칸도 충분하면 `X3`, 모자라면 `1/3`처럼 보유량을 같이 띄운다. **비활성 버튼만 던져놓으면 플레이어는 이유를 모른다.**

### 5-7. 전투 (`BattleManager`) — 제일 깊게 파고들어야 할 부분

**턴 구조**: 플레이어 행동 1회 → 적 행동 1회. 예외는 급습(적이 먼저 움직임)과 약 사용(공격 없이 적 턴만 넘어감).

**플레이어 행동 5종**

| 행동 | 효과 | 스태미나 |
|------|------|----------|
| 공격 | 공격 5종 중 선택 | 공격마다 다름 (기본 3) |
| 방어 | 이번 적 공격 피해 **50% 감소** | 1 |
| 회피 | **30% 확률**로 이번 적 공격 완전 무효 | 1 |
| 약 | 버프. 대신 적한테 한 턴 내줌 | 0 |
| 도주 | 전투만 종료. 승도 패도 아님 | 0 |

**공격 5종 (`AttackSO`)** — 코드는 하나고 데이터가 다르다

| 필드 | 의미 |
|------|------|
| `powerPercent` | 내 공격력 대비 위력 (100이면 그대로) |
| `element` | **이 공격의 오행.** 상성은 내 속성이 아니라 이걸로 따진다 |
| `hitCount` | 연타 횟수. **한 대마다 따로 적 방어를 뺀다** |
| `ignoreDefense` | 적 방어 무시 |
| `enemyMovesFirst` | 적이 먼저 움직인 뒤 내 공격이 들어감 (급습) |

- **연타는 단단한 적한테 약하다.** 방어를 매 타 빼기 때문. 물몸 다수타에 강하고 탱커한테 약한 구도가 자연스럽게 나온다.
- **급습은 뜸을 들이는 대신 적이 반격할 턴이 없다.** 다만 뜸 들이는 사이에 쓰러지면 공격이 아예 안 나간다.
- **공격마다 속성이 따로다.** 그래서 내 속성이 안 맞아도 맞는 속성 공격을 골라 대응할 수 있다.

**오행 상극**
```csharp
목 → 토,  토 → 수,  수 → 화,  화 → 금,  금 → 목   (1.2배)
```
플레이어 → 적 방향, 적 → 플레이어 방향 **양쪽 다 적용된다.**

**데미지 공식 — 여기서 실제 버그를 잡았다 (발표 하이라이트)**

```
[기존]  피해 = (공격력 - 방어력),  상성이면 (int)(피해 × 1.2)
[수정]  상성이면 공격력에 먼저 1.2배 (반올림), 그 다음 방어력을 뺀다
```

문제가 두 개였다.
1. **`(int)` 버림 때문에 피해가 4 이하면 상성 보너스가 0이었다.** 이득이 `내림(피해 × 0.2)`이라 피해 4면 `내림(0.8)` = 0. 상성이 아예 없는 것과 같았다.
2. **방어를 뺀 뒤에 곱해서, 단단한 적일수록 상성이 무력했다.** 상성이 제일 필요한 순간에 상성이 사라지는 구조였다.

곱하는 순서를 바꾸고 반올림으로 고치니 **상성이 실제로 작동한다.** 검증: 토 속성 알파전이 6클릭 → 5클릭으로 줄었다.

> 이건 "구현했는데 안 돌아가는 걸 발견해서 원인을 정확히 짚고 고쳤다"는 **가장 개발자다운 소재**다. 발표에서 밀면 좋다.

**적 행동 패턴 (`EnemyAction`)**
```csharp
enum EnemyActionType { Attack, StrongAttack, Defend }
```
적마다 행동 배열을 넣으면 **순서대로 반복**한다 (예: 공격 → 공격 → 강공격). 배열이 비면 일반 공격만 한다.
- 방어는 **1회성**이다. 플레이어가 한 대 때리면 사라진다.
- **다음 행동이 UI에 예고된다.** 그래서 "강공격 예고 → 방어나 회피" 같은 판단이 성립한다. 예고 없이 랜덤이면 방어/회피가 그냥 도박이 된다.

**약 버프 — 두 번째로 고친 버그**

```csharp
private class Buff { public int attack, defense, turns; }
private readonly List<Buff> buffs = new List<Buff>();
```

세 단계로 고쳤다.

| 단계 | 문제 |
|------|------|
| 원래 (대입) | 각성제 먹고 진통제 먹으면 **각성제 효과가 사라짐.** "약 챙겨가서 버프" 컨셉과 정면 충돌 |
| 1차 수정 (`+=`) | 버프 시간이 하나로 공유돼서, **3턴짜리를 3턴마다 다시 먹으면 첫 약효가 영원히 유지됨.** 지속 0인 약은 영구 버프 |
| 최종 (리스트) | **약 하나하나가 따로 걸리고 각자 시간을 센다.** 먼저 먹은 약이 자기 시간에 맞춰 먼저 떨어짐 |

- 약값은 **적에게 한 턴을 내주는 것**이다 (기획서 그대로).
- 약효 시간은 **공격할 때만 줄어든다.**
- 이 두 규칙 덕에 **약 남용이 규칙이 아니라 손익으로 억제된다.** 3단계 시뮬레이션 결과: 각성제 2개가 최적(잔여 42), 3개는 오히려 나빠짐(28), 5개는 더 나빠짐(21). **"보스전 전에 약을 모아라"가 실제 전략이 된다.**

### 5-8. 씬 구조 — 전투를 씬 위에 얹는다

두 개가 Additive로 얹힌다.

**① 상단 HUD (`UpperUISceneLoader` → State 씬)**
모든 게임 씬이 `Awake`에서 HUD 씬을 Additive로 얹는다. 이미 있으면 안 얹는다. 씬마다 HUD를 복붙하면 수정할 때 5군데를 고쳐야 하는데, 이러면 한 군데다.

**② 전투 화면 (`BattleSceneLoader` → Battle 씬)**
```csharp
bool inBattle = battleManager.InBattle();
if (inBattle) SceneManager.LoadScene(battleSceneName, LoadSceneMode.Additive);
else SceneManager.UnloadSceneAsync(scene);
```
전투가 시작되면 전투 씬을 **위에 얹고**, 끝나면 내린다.

> **왜 씬을 갈아타지 않나 (중요한 답변)**: 씬을 갈아타면 탐사 상태 — 지금 깊이가 얼마인지, 어떤 이벤트를 뽑아뒀는지 — 가 전부 날아간다. 그러면 전투 후 탐사를 이어갈 수가 없다. 얹는 방식이면 아래 씬이 그대로 살아 있어서 전투가 끝나는 순간 이어서 진행된다.

**`BattleOverlay`** — 얹힌 전투 씬이 **자기 매니저를 쓸지 아래 씬 매니저를 쓸지** 스스로 판단한다.
```csharp
BattleManager live = FindLiveBattleManager();   // 이 씬 밖에서 이미 돌고 있는 것
if (live == null) { /* 혼자 열렸다 → 자기 매니저·카메라 켬 */ }
else Bind(live);                                 // 얹혔다 → 화면만 바깥 전투에 물림
```
덕분에 **Battle 씬을 단독으로 열어서 전투만 따로 테스트할 수도 있고**, 탐사/연구 위에 얹혀서도 돈다. 같은 씬 하나로 둘 다 된다.

### 5-9. 랭킹 (`RankManager`) — 여기도 버그를 잡았다

public void AddRank(string playerName) {
    Load();                                   // ← 이게 없어서 기록이 전부 날아갔다
    ...
    rankList.Sort((a, b) => a.clearDay.CompareTo(b.clearDay));   // 일수 오름차순

**버그**: 이름을 넣는 건 연구 씬의 `RankManager`인데, **얘는 저장된 기록을 한 번도 읽은 적이 없는 객체였다.** 그대로 저장하면 이번 판 하나만 남고 예전 기록이 전부 날아갔다. → `AddRank` 맨 앞에서 `Load()`를 먼저 하도록 고쳤다.

- 저장은 `PlayerPrefs` + `JsonUtility`. 리스트는 JsonUtility가 최상위 배열을 직렬화 못 해서 **래퍼 클래스에 담아서** 넘긴다.
- 상위 10개만 남긴다. 안 그러면 저장 문자열이 끝없이 길어진다.
- 이름이 비면 "이름없음"으로 넣는다.

### 5-10. 스토리 / 엔딩 (`StoryUI` / `EndingUI`)

`StoryUI` 하나를 **인트로와 엔딩이 공유한다.** 페이지 배열과 체크박스 두 개(`playOnStart` / `oncePerRun`)만 다르게 준다.
- 인트로: 씬 시작 시 자동 재생 + 한 판에 한 번만
- 엔딩: 자동 재생 끔. `EndingUI`가 `vaccineProgress >= 100`을 감지해서 재생

로비로 돌아오면 `LobbyUI.Awake`에서 `StoryUI.ResetIntro()`와 `IngameBootstrap.ResetRun()`을 부른다. **시작 버튼이 아니라 로비 진입 시점에 초기화하는 이유**: 어느 경로로 들어오든(게임오버 → 로비, 클리어 → 로비) 무조건 새 판이 되게 하려고.

### 5-11. 사운드 (`SoundManager`)

싱글턴 + `DontDestroyOnLoad`. BGM/SFX를 배열 인덱스로 재생한다.
```csharp
private bool Has(AudioClip[] clips, int index) {
    return clips != null && index >= 0 && index < clips.Length && clips[index] != null;
}
```
**아직 클립을 안 넣은 자리는 조용히 넘어간다.** 없는 번호로 불러도 재생만 안 될 뿐 게임은 굴러가야 한다. 전투의 효과음 번호는 전부 `-1`(소리 없음)이 기본값이라, **사운드가 안 붙어도 전투는 정상 동작한다.**

### 5-12. 개발 도구 (`Dev/` + `Editor/`)

이건 "그냥 만들기만 한 게 아니라 검증했다"는 증거다.

**테스트 씬 4개 + 러너 5개** — 씬 UI 없이 시스템만 굴려본다.
- `BattleTestRunner`: Space 공격 / 1,2 약 / R 재시작. 전투 수치를 눈으로 확인
- `IngameLoopTestRunner`: D 하루시작 / T 턴소모 / C 백신100. 물자·체력·의식이 어떻게 물리는지 확인
- `ExplorationTestRunner`, `ResearchTestRunner`, `UpperUITestRunner`

**에디터 도구 2개** (Tools 메뉴)
- `씬 상태 검사`: 5개 씬을 돌면서 **어떤 컴포넌트가 안 붙어 있는지 콘솔에 뽑아준다.** 씬은 바이너리라 코드로 못 여니까, 배선 누락을 사람이 눈으로 찾는 대신 도구가 찾게 했다

## 6. 밸런스 — 숫자를 왜 그렇게 뒀는가

### 6-1. 최종 수치

| 항목 | 값 | 이유 |
|------|-----|------|
| 하루 최대 턴 | **1** | 1밤 = 1일. "N일 제한"이 실제 N밤이 됨 |
| 시작 날짜 | **14일** | 목표 클리어 10~12밤 기준 |
| 공격력 / 방어력 | **12 / 6** | 3단계 클리어 가능 최소선 |
| 최대 스태미나 | **12** | 도시 지역 한도 12가 잘리던 문제 해소 |
| 일일 회복 | **3** | 회복이 소비·페널티를 다 덮어버리던 문제 |
| 일일 소비 | **5** | 순 -2/밤이라 물자 고갈이 실제 위협 |
| 시작 물자 | **14** | 3밤째 고갈 → 이후 물자 관리가 선택이 됨 |
| 의식 감소 | **8/일** | 9밤째 혼미 진입 |
| 혼미 체력 페널티 | **6/일** | 회복(3)에 흡수되지 않게 |

### 6-2. 밸런스에서 발견한 문제들 (이게 더 중요하다)

수치를 "그냥 감으로 정한 게 아니라 문제를 찾아서 고쳤다"는 게 핵심이다.

| 발견한 문제 | 실측 | 왜 문제인가 | 조치 |
|------------|------|------------|------|
| 데드라인이 무의미 | 예산이 30밤이 아니라 **150밤** | `maxTimeTurn=5`라 5번 복귀해야 하루 | maxTimeTurn 1 |
| 의식이 발동조차 안 함 | 임계 30까지 **14밤** 필요 | 6밤 런에선 절대 안 걸림 | drift 5→8 |
| **굶는 쪽이 이득** | 회복 5 > 소비 3 | 물자를 안 먹는 게 유리했다 | 회복 3 / 소비 5 |
| 지역 차별화 소멸 | 도시 12 → 런타임 **10** | `stamina.max`가 10이라 Clamp에 잘림 | max 12 |
| 3단계를 이길 수 없음 | 시뮬레이션상 **패배** | 공10/방5로는 베타+숙주 연전 불가 | 공12/방6, 숙주 hp 60→47 |
| 고아 에셋 | `Item_SampleBox` | 어떤 이벤트에서도 안 나옴 | 바다 창고 이벤트에 배치 |

### 6-3. 시뮬레이션 검증 결과

전투를 **턴 단위로 시뮬레이션**해서 수치를 확정했다. (공12 / 방6 / 숙주 hp47·공11 기준)

| 상황 | 결과 |
|------|------|
| 연구 1단계 (알파) | 승 · 잔여 체력 88 · 5클릭 |
| 연구 2단계 (베타) | 승 · 잔여 체력 70 · 7클릭 |
| **연구 3단계 (베타+숙주)** | 승 · **잔여 체력 14** · 16클릭 |
| 탐사: 갈매기 / 멧돼지 / 드론 | 96 / 86 / 72 · 3 / 4 / 6클릭 |

**3단계는 아슬아슬하게 이기게 맞췄다.** 최종보스가 여유롭게 잡히면 클라이맥스가 안 산다.

**약 사용에 따른 3단계 잔여 체력** — 남용이 손익으로 억제되는지 확인

| 각성제 | 0개 | 1개 | 2개 | 3개 | 5개 |
|--------|-----|-----|-----|-----|-----|
| 잔여 | 14 | 21 | **42** | 28 | 21 |

**2개가 최적, 그 이상은 오히려 손해.** 약을 마실 때마다 적에게 한 턴을 내주기 때문이다. 별도 제한 규칙 없이 **구조만으로 남용이 억제된다.**

> **질문 대비**: "밸런스는 어떻게 잡았어요?" → "손으로 플레이하면서 감으로 맞추는 대신, 전투를 턴 단위로 시뮬레이션해서 검증했습니다. 그 과정에서 '굶는 게 이득'이라거나 '3단계를 아예 못 이긴다' 같은 문제를 발견했고, 수치를 고친 뒤 다시 돌려서 클리어 가능한 걸 확인했습니다."

## 7. 발표 하이라이트 — 이 5개만 밀어도 된다

기술 질문이 오면 여기서 답을 꺼낸다. 전부 **"문제 발견 → 원인 분석 → 해결"** 구조라 말하기 좋다.

### ① ScriptableObject가 씬 전환 중에 언로드돼서 진행도가 날아간 문제
탐사 입구 씬을 거치면 모은 샘플이 전부 0이 됐다. 원인은 그 씬에 `GameState`를 참조하는 오브젝트가 하나도 없어서 Unity가 에셋을 메모리에서 내렸다가 파일에서 다시 읽은 것. `hideFlags = DontUnloadUnusedAsset`으로 해결.

### ② 오행 상성이 코드에는 있는데 실제로는 작동하지 않던 문제
`(int)` 버림 때문에 피해가 4 이하면 보너스가 0이었고, 방어를 뺀 뒤에 곱해서 단단한 적한테는 상성이 무력했다. **곱하는 순서를 방어 차감 앞으로 옮기고 반올림으로 바꿨다.** 상성이 제일 필요한 순간에 상성이 살아난다.

### ③ 약 버프가 서로를 덮어쓰던 문제
대입이라 각성제 먹고 진통제 먹으면 각성제가 사라졌다. `+=`로 바꿨더니 이번엔 시간이 공유돼서 영구 버프가 생겼다. 최종적으로 **버프를 리스트로 만들어 약마다 따로 타이머를 돌게** 했다.

### ④ 전투 씬을 얹는 방식으로 바꿔서 탐사 상태를 보존
씬을 갈아타면 탐사 깊이와 뽑아둔 이벤트가 날아간다. Additive로 위에 얹고 끝나면 내리는 구조로 바꿨다. `BattleOverlay`가 "이미 돌고 있는 전투가 있는지"를 스스로 판단해서, **같은 씬 하나로 단독 테스트와 오버레이 양쪽을 다 처리한다.**

### ⑤ 밸런스를 감이 아니라 시뮬레이션으로 검증
"굶는 게 이득", "3단계를 못 이김", "데드라인이 실제로는 5배" 같은 문제를 수치 시뮬레이션으로 찾아냈다.

**보너스 소재들**
- 랭킹이 저장할 때마다 이전 기록을 날리던 버그 (`Load()` 누락)
- 밤에 눌러앉아 쉬기만 하면 대가 없이 샘플을 무한 수급하던 구멍
- 전투 중에 연구 카드를 또 누르면 샘플만 깎이고 전투가 덮어써지던 버그
- 버튼 클릭 리스너의 **클로저 인덱스 캡처** 문제 (`for`의 `i`를 그대로 넘기면 눌릴 때는 이미 마지막 값). `int index = i;`로 따로 받아둠 — `ItemUI`, `AttackSelectUI`, `ResearchUI` 전부 해당

## 8. 현재 상태 / 남은 작업 — 솔직하게 말할 부분

> 데모에서 뭔가 안 보이거나 어색하면 **여기 있는 걸로 답한다.** 얼버무리는 것보다 정확히 아는 게 낫다.

### 코드는 다 있는데 씬 배선이 남은 것

씬 파일과 ScriptableObject는 **Unity 바이너리 포맷**이라 코드로 못 고친다. 인스펙터에서 사람이 직접 연결해야 한다. 그래서 "스크립트는 있는데 씬에 안 붙어 있는" 상태가 일부 남아 있다.

- 깨진 참조(Missing Script)는 **0건**이다. 스크립트가 아예 안 붙은 것뿐이라 붙이면 바로 된다.
- 어디가 비었는지는 **에디터 도구(`Tools > 백신 서바이벌 > 씬 상태 검사`)가 콘솔에 뽑아준다.**

> **답변 템플릿**: "그 부분은 로직은 다 짜여 있고 씬에 컴포넌트를 붙이는 배선만 남았습니다. 씬 파일이 바이너리라 병합·자동화가 안 돼서 마지막에 몰아서 하고 있고, 어디가 비었는지 검사해주는 에디터 도구를 따로 만들어 뒀습니다."

### 데모 전에 확인해야 할 것들

| 항목 | 확인 |
|------|------|
| 빌드 세팅 | Lobby(0), Ingame, Research, Adventure_Enter, Adventure, State, Battle 전부 등록 |
| 컴파일 | Ctrl+R 후 콘솔 에러 0건 |
| `GameState.asset` | 인스펙터에서 한 번 건드려 저장 (구 스키마 갱신) |
| HUD 바 | `Image Type`을 **Filled**로 (아니면 텍스트만 나옴) |
| 얼굴 스프라이트 | 3장 없으면 같은 것 3장이라도 넣기 (`FaceDisplay`는 색 대체 폴백이 있긴 함) |

### 알려진 수치 충돌 — 데모 전에 손보면 좋은 것 2개

**⚠️ 연구 입장 비용 20 > 최대 스태미나 12**
탐사에서 스태미나를 남기고 돌아온 상태로 연구에 들어가면, 입장 비용 20이 한 번에 빠져서 **스태미나가 0이 되고 아이템 50% 손실 패널티까지 같이 터진다.** (스태미나가 이미 0이면 `Spend`가 막혀서 아무 일도 안 일어난다 — 게임 시작 직후 첫 연구는 무료다.)
→ 데모 전에 `ResearchManager.enterStaminaCost`를 **5 이하로** 내리거나 `startMaxStamina`를 올려두는 게 안전하다.

**⚠️ 깊이 비용 10×깊이 > 스태미나 한도 8~12**
"더 들어가기" 한 번이 스태미나 10을 먹는데 지역 한도가 8~12다. 현재 수치에서는 **깊이 시스템이 사실상 한 번 쓰면 복귀하는 버튼**이다.
→ 깊이를 시연할 거면 `ExplorationManager.deeperStaminaCost`를 **3 정도로** 낮춰두면 화면에서 보인다.

> 물어보면: "밸런스 검증을 전투 위주로 먼저 돌려서 탐사 쪽 수치 정합성은 아직 조정 중입니다. 시스템은 다 돌아가고 인스펙터 값만 바꾸면 되는 부분입니다."

| 기능 | 상태 |
|------|------|

## 9. 예상 질문 & 답변

### A. 기획 / 컨셉

**Q. 한 줄로 어떤 게임인가요?**
> 한의사가 좀비 아포칼립스에서 제한된 날짜 안에 백신을 만드는 턴제 생존 게임입니다. 낮에 연구하고 밤에 샘플을 캐러 나가는 낮/밤 루프가 핵심입니다.

**Q. 왜 좀비/바이러스인가요? 흔하지 않나요?**
> 소재는 흔한데 주인공이 다릅니다. 총 든 군인이 아니라 한의사고, 싸워서 이기는 게 아니라 **치료제를 만들어서** 이깁니다. 그래서 전투가 목적이 아니라 샘플을 얻기 위한 수단이 됩니다.

**Q. 왜 오행인가요?**
> 주인공이 한의사라서요. 흔한 원소 상성을 한의학 오행으로 갈아끼운 겁니다. 상극 관계 다섯 개를 그대로 코드에 넣었고, 적과 지역에도 속성을 부여했습니다.

**Q. 핵심 재미가 뭐라고 생각하세요?**
> "한 번 더 나갈까"입니다. 밤에 더 나가면 샘플을 더 얻지만 날짜가 줄고 몸이 상합니다. 매 턴 그 저울질을 하게 만드는 게 목표였습니다.

**Q. 플레이 타임은요?**
> 한 판에 10~12밤, 실시간 15~20분 정도를 목표로 잡았습니다. 클리어 일수가 랭킹 점수라 반복 플레이로 기록을 줄이는 구조입니다.

**Q. 목표 플랫폼은요?**
> PC입니다. 마우스 클릭만으로 조작이 되게 만들었습니다.

**Q. 리플레이 가치는요?**
> 세 가지입니다. 첫째, 이벤트가 지역마다 7개씩 랜덤이라 매 판 다릅니다. 둘째, 지역 속성이 내 속성이 돼서 어느 지역을 언제 가느냐가 전투 상성을 바꿉니다. 셋째, 클리어 일수 랭킹이 남아서 최적화 동기가 생깁니다.

### B. 시스템

**Q. 하루가 어떻게 지나가나요?**
> 시간은 실시간이 아니라 행동으로 흐릅니다. 탐사에서 복귀하거나 휴식하면 시간 턴이 1 줄고, 0이 되면 하루가 넘어갑니다. 하루가 넘어갈 때 물자를 소비하고, 체력이 회복되고, 의식이 떨어집니다.

**Q. 의식 게이지는 뭔가요?**
> 주인공만 의식이 남았다는 설정을 게임 시스템으로 만든 겁니다. 100에서 시작해 매일 8씩 떨어지고 30 이하가 되면 혼미 상태가 됩니다. 혼미면 자연회복이 막히고 매일 체력이 추가로 6씩 깎입니다. 상단 얼굴 그림이 3단계로 흐려져서 눈으로 보입니다.

**Q. 혼미 페널티가 왜 회복을 막는 방식인가요?**
> 원래는 체력 -3이었는데 자연회복이 +5라서 혼미에 빠져도 순이득이었습니다. 페널티가 페널티가 아니었죠. 회복 자체를 막아야 실제 압박이 됩니다.

**Q. 스태미나는 어디에 쓰나요?**
> 밤 자원입니다. 탐사를 시작하면 그 지역 한도로 채워지고, 선택지·전투·더 들어가기에 소모됩니다. 0이 되면 가진 아이템 절반을 잃고 강제 복귀합니다. 지역마다 한도가 달라서 지역 선택 자체가 전략이 됩니다.

**Q. 샘플은 왜 세 종류인가요?**
> 연구 단계마다 요구 조합이 달라서, 한 지역만 파면 안 되게 만들려고요. 3단계로 갈수록 세 종류를 다 요구해서 자연스럽게 세 지역을 다 돌게 됩니다.

**Q. 깊이 시스템은요?**
> 탐사 중에 안쪽으로 더 들어가면 샘플을 깊이만큼 더 얻습니다. 대신 들어갈 때마다 스태미나가 더 비싸집니다. 보너스를 곱셈이 아니라 덧셈으로 준 게 포인트인데, 곱하면 큰 선택지만 계속 불어나서 깊이가 무조건 정답이 돼버립니다.

**Q. 아이템은 몇 종류고 어떻게 쓰나요?**
> 7종입니다. 회복류(붕대·구급상자), 물자(통조림), 샘플(샘플상자)는 벙커에서 쓰고, 약류(각성제·진통제·진정제)는 전투 중에만 씁니다. `ItemManager`가 약 타입이면 아예 거부해서 전투 밖에서 못 쓰게 막았습니다.

**Q. 랭킹은 어떻게 저장하나요?**
> `PlayerPrefs`에 `JsonUtility`로 JSON 문자열을 넣습니다. 클리어까지 걸린 일수 오름차순으로 정렬하고 상위 10개만 남깁니다. `JsonUtility`가 최상위 리스트를 직렬화 못 해서 래퍼 클래스에 담아 넘깁니다.

### C. 기술 / 구조

**Q. 왜 ScriptableObject를 썼나요?**
> 두 가지입니다. 첫째, 기획 수치를 코드에서 분리했습니다. 적·이벤트·아이템·연구 단계가 전부 에셋이라 새 이벤트를 추가할 때 코드를 안 건드립니다. 둘째, 게임 상태 전체를 `GameState` 에셋 하나에 모아서 씬을 넘어도 유지되게 했습니다. 싱글턴보다 인스펙터에서 값이 보여서 디버깅이 훨씬 편합니다.

**Q. `DontDestroyOnLoad` 싱글턴 안 쓴 이유는요?**
> 싱글턴이면 어느 씬에서 시작하든 그 오브젝트가 있어야 해서 씬 단위 테스트가 어렵습니다. SO는 파일이라 씬과 무관하게 존재하고, 인스펙터에서 실시간으로 값이 보입니다. 실제로 테스트 씬 4개를 그 덕에 독립적으로 돌릴 수 있었습니다.

**Q. 상태를 한 곳에 모으면 결합도가 높아지지 않나요?**
> 데이터는 모았지만 **로직은 매니저별로 분리**했습니다. 물자를 건드리는 건 `SupplyManager`뿐이고, 시간은 `TimeManager`뿐입니다. 데이터가 한 곳이라 상태 불일치가 없고, 로직은 나뉘어 있어서 어디가 뭘 바꾸는지는 명확합니다.

**Q. 전투 코드가 연구와 탐사에서 어떻게 재사용되나요?**
> `BattleManager`가 UI를 전혀 모르고 승리/패배 콜백만 받습니다. 연구는 "이기면 다음 적 소환", 탐사는 "이기면 보상 주고 탐사 계속"을 콜백으로 넘깁니다. 전투 로직 자체는 한 벌입니다.

**Q. 씬 전환은 어떻게 처리했나요?**
> 화면 전체가 바뀌는 건 `LoadScene`으로 갈아타고, 상단 HUD와 전투 화면은 **Additive로 위에 얹습니다.** 특히 전투를 얹는 게 중요한데, 씬을 갈아타면 탐사 깊이와 뽑아둔 이벤트가 날아가서 전투 후 이어서 진행할 수가 없습니다.

**Q. 씬이 바이너리인데 협업은 어떻게 했나요?**
> 그게 실제로 제일 아팠던 부분입니다. 씬 파일은 병합이 안 되니까 **한 사람이 한 씬**을 원칙으로 나눴고, 로직은 전부 스크립트와 SO로 빼서 텍스트 단위 병합이 되게 했습니다. 그리고 씬 배선 누락을 콘솔에 뽑아주는 에디터 도구를 따로 만들었습니다.

**Q. 테스트는 어떻게 했나요?**
> 시스템별 테스트 씬을 따로 만들었습니다. 전투는 UI 없이 키보드로 굴려보면서 수치를 확인하고, 하루 루프는 키 하나로 하루를 넘겨가며 물자·체력·의식 변화량을 봤습니다. 전투 밸런스는 턴 단위 시뮬레이션으로 검증했습니다.

**Q. 성능은요?**
> UI를 매 프레임 갱신하는 구조지만 실제 갱신 대상이 HUD 몇 개라 부하가 없습니다. 2D 턴제라 연산 부하 자체가 거의 없고, 전투 씬을 Additive로 얹었다 내리는 것도 씬 하나 크기라 체감이 없습니다. 다만 규모가 커지면 이벤트 기반으로 바꾸는 게 맞습니다.

**Q. 코드 규모는요?**
> C# 스크립트 69개, ScriptableObject 에셋 45개, 씬 15개입니다.

### D. 밸런스

**Q. 난이도는 어떻게 조절했나요?**
> 감으로 맞추지 않고 전투를 턴 단위로 시뮬레이션했습니다. 그 과정에서 "3단계를 아예 못 이긴다"는 걸 발견해서 공격력과 보스 체력을 조정했고, 다시 돌려서 잔여 체력 14로 아슬아슬하게 이기는 걸 확인했습니다. 최종보스는 여유롭게 잡히면 안 된다고 봤습니다.

**Q. 약을 무한정 먹으면 되는 거 아닌가요?**
> 약을 마실 때마다 적에게 한 턴을 내줍니다. 시뮬레이션 결과 각성제 2개일 때 잔여 체력 42로 최적이고, 3개면 28, 5개면 21로 오히려 나빠집니다. **제한 규칙 없이 구조만으로 남용이 억제됩니다.** 대신 "보스전 전에 약을 모아라"가 실제 전략이 됩니다.

**Q. 시간 제한이 너무 빡빡하지 않나요?**
> 14일에 목표 클리어가 10~12밤이라 여유가 2~4밤입니다. 그 여유가 "한 번 더 나갈까"를 고민하게 만드는 폭입니다. 여유가 크면 고민이 사라지고, 없으면 그냥 답이 하나가 됩니다.

**Q. 밸런스 작업 중에 발견한 게 있나요?**
> 제일 황당했던 건 **굶는 쪽이 이득**이었던 겁니다. 자연회복이 5인데 하루 소비가 3이라, 물자를 안 먹고 체력으로 때우는 게 유리했습니다. 생존 게임에서 굶는 게 이득이면 시스템이 죽은 겁니다. 회복 3 / 소비 5로 뒤집어서 밤마다 순 -2가 되게 했습니다.

**Q. 랜덤 요소가 운빨 아닌가요?**
> 랜덤은 두 군데뿐입니다. 이벤트 추첨과 회피 확률 30%. 이벤트는 지역별 7개 중에 나오고 **직전 것이 안 나오게** 처리했고, 회피는 방어라는 확정 선택지가 따로 있어서 강제되지 않습니다. 적 행동은 완전 결정론적이고 **다음 행동이 화면에 예고**됩니다. 그래서 운이 아니라 판단으로 풀 수 있습니다.

### E. 개발 과정 / 협업

**Q. 제일 어려웠던 게 뭐예요?**
> 씬 전환 중에 진행도가 통째로 날아가는 문제였습니다. 특정 씬을 거칠 때만 샘플이 0이 돼서 재현 조건 찾는 데 오래 걸렸는데, 원인이 그 씬에 `GameState`를 참조하는 오브젝트가 하나도 없어서 Unity가 에셋을 언로드했다가 파일에서 다시 읽은 거였습니다. `hideFlags`를 세워서 해결했습니다.

**Q. 구현했는데 안 돌아갔던 건 없나요?**
> 오행 상성이 그랬습니다. 코드는 다 있는데 실제로는 거의 작동을 안 했습니다. 정수 버림 때문에 피해가 4 이하면 보너스가 0이 되고, 방어를 뺀 뒤에 곱해서 단단한 적일수록 상성이 무력해졌습니다. **상성이 제일 필요한 순간에 사라지는 구조**였던 거죠. 곱하는 순서를 방어 차감 앞으로 옮기고 반올림으로 바꿔서 고쳤습니다.

**Q. 역할 분담은요?**
> 저는 게임 로직과 데이터 구조를 맡았고, UI와 아트, 씬 연출은 팀원이 맡았습니다. 커밋에 접두어를 붙여서 누가 뭘 건드렸는지 추적할 수 있게 했습니다.

**Q. 버전 관리는요?**
> Git입니다. 씬 파일이 바이너리라 충돌이 나면 병합이 안 되니까, 한 사람이 한 씬을 맡는 걸 원칙으로 하고 로직은 전부 스크립트로 빼서 텍스트 병합이 되게 했습니다.

**Q. 다시 만든다면 뭘 바꾸겠어요?**
> 세 가지입니다. 첫째, UI를 매 프레임 폴링이 아니라 이벤트 기반으로 바꾸겠습니다. 둘째, 게임오버 판정이 `GameManager`와 `ResultUI` 두 군데 있는데 한 곳으로 모으겠습니다. 셋째, 씬 배선을 처음부터 프리팹으로 묶었으면 후반에 배선 작업이 몰리지 않았을 겁니다.

**Q. 앞으로 뭘 더 할 건가요?**
> 우선순위는 세이브/로드 완성, 사운드 배치, 대화 시스템을 본편 루프에 연결하는 겁니다. 그다음이 이벤트 추가인데, 데이터가 SO로 분리돼 있어서 코드 없이 늘릴 수 있습니다.

### F. 대답하기 곤란할 때

                깊이 최대 3 · 깊이당 샘플 +depth · 비용 10×깊이
                스태미나 0 → 아이템 50% 손실 + 강제 복귀
                휴식 = 시간 턴 1 소모 + 스태미나 회복

■ 연구          1→2→3 순차 해금 · 입장 시 스태미나 20 (전투 중엔 소모 없음)
                3단계 = 변이체 베타 → 숙주 연전 (약효 유지)
